1. Missão e princípios

Nome: Radar Cripto EGI. Frase: “O mercado fala. Nós investigamos.” Formato: canal e portal público com notícias verificadas, análises de BTC e altcoins e resultados dos laboratórios EGI.

  • Mostrar hipóteses, regras, dados e resultados, incluindo erros e testes inconclusivos.
  • Diferenciar notícia, opinião, sinal, simulação, análise retrospectiva e execução real.
  • Não prometer lucro nem apresentar uma pontuação como garantia.
  • Preservar os aplicativos operacionais privados em repositórios separados.

Princípio editorial: “O indicador sugere; o candle fechado confirma. A ideia merece registro, não obediência.”

3. Como publicar no GitHub Pages

  1. Entrar no repositório Radar_Cripto_EGI no GitHub.
  2. Verificar se index.html está na raiz da branch main.
  3. Em Settings → Pages, escolher Deploy from a branch, main e pasta /(root).
  4. Salvar e abrir o site oficial. Depois de cada atualização, confirmar que as páginas principais abrem.

Para editar arquivos pequenos: abra o arquivo no GitHub → lápis Edit → faça alterações → Commit changes. Para mudanças extensas, prefira guardar uma cópia antes de substituir.

Erro 404: conferir nome exato do repositório, branch, pasta e presença do index.html. Um endereço novo pode levar alguns minutos para refletir o deploy.

4. Publicação de vídeos, notícias e estudos

Vídeos

  1. Preparar roteiro, título, descrição e fontes.
  2. Publicar efetivamente o vídeo no canal oficial do YouTube.
  3. Só depois colocar o link confirmado na Central e acrescentar uma nova entrada ao feed RSS.

Notícias verificadas

Editar config.js e preencher noticias com notícias datadas e com URL real da fonte. O portal aceita uma seleção de domínios de notícias; links fora dessa lista podem não ser exibidos até atualização do código. Exemplo ilustrativo, não é uma notícia real:

noticias: [
  {
    titulo: "Título verificado",
    data: "2026-11-01",
    fonte: "Fonte publicada",
    url: "https://www.reuters.com/...",
    resumo: "Resumo fiel aos fatos."
  }
]

Não divulgar manchetes imaginárias nem dados de mercado históricos como se fossem cotações de agora. Para novos posts publicados, atualizar também o feed.xml com título, link e descrição.

6. Laboratório EGI — padrão para divulgar resultados

Cada teste deve mostrar ativo, direção, data/hora e fuso, fonte de candles, timeframe, critérios, quantidade de amostras, horizonte de auditoria, resultado, erros e limitações.

A edição inicial usou a fotografia de 30/10/2026, 18h44min59s BRT, com seis ativos UNI, LQTY, CHZ, 0G, GNS e ALGO, em candles de 15m, conforme RelEGI V1.8 (2). A Central exibe o resultado direcional após 3 candles; os horizontes +6 e +12 estavam pendentes no material utilizado.

Uma variação percentual após a hipótese não é uma ordem de trading nem lucro líquido. Taxas, spread, risco, slippage e execução real devem ser identificados separadamente.

7. Backup e recuperação do projeto

  1. Abra o repositório oficial, escolha Code → Download ZIP. Guarde o ZIP com a data, por exemplo Radar_Cripto_EGI_backup_2026-11-01.zip.
  2. Guarde uma cópia deste manual-mestre.html fora do GitHub e dos arquivos HTML/JSON/TXT dos relatórios EGI usados nas matérias.
  3. Baixe e guarde também as anotações do caderno no botão Exportar anotações JSON ao final da página. Elas não são sincronizadas com o repositório.
  4. Antes de alterar o portal, identifique a última versão íntegra e registre o que foi mudado. Faça alterações primeiro em uma cópia quando o risco for alto.
  5. Se o site sair do ar, restaure o ZIP preservando a raiz do repositório, a branch main e a configuração do GitHub Pages.

Importante: esta apostila documenta o projeto; não substitui um backup de todos os arquivos. O ZIP do repositório é a cópia de código. As anotações locais são armazenadas somente neste navegador até você exportá-las.

8. Privacidade, direitos e segurança

  • GitHub Pages é público. Nenhuma chave Binance, MEXC, Telegram bot, credencial privada ou lista de e-mails pode ser escrita nos arquivos públicos.
  • Publicar apenas imagens, textos, vídeos e trechos com direitos de uso. Ao comentar uma live, preferir síntese própria e atribuição de fonte.
  • Para coletar contatos, informar a finalidade, responsável, meio de contato, prazo de retenção, correção/exclusão e descadastro em conformidade com a legislação aplicável.
  • Não declarar sucesso de inscrições antes de testar ponta a ponta a coleta, confirmação e o cancelamento.

12. Área editorial privada e resgate de rascunhos

Desde a V1.4.1, o Painel Editorial completo está guardado em uma pasta independente de um repositório GitHub privado, separado deste site público. Os responsáveis autorizados podem baixar o arquivo HTML, abrir offline e trabalhar com rascunhos e estudos internos.

Como recuperar registros antigos

  1. No mesmo aparelho, navegador e perfil usados no editor público, abrir a página de resgate de rascunhos.
  2. Selecionar Exportar meus rascunhos JSON e guardar o arquivo.
  3. Na pasta privada Radar_Cripto_EGI_Privado do repositório GitHub privado Meus_Projetos, baixar painel-editorial.html para o próprio aparelho.
  4. Abrir o HTML offline e usar Restaurar JSON anteriormente exportado. Verificar os registros e manter cópia separada dos backups.

Os rascunhos eram salvos no navegador, não no GitHub. Eles não são transferidos automaticamente para a área privada. O Caderno de Evolução deste manual possui armazenamento independente e precisa de backup próprio.

A antiga versão do código editorial pode continuar acessível no histórico público de commits do GitHub. A mudança protege a versão funcional atual e mantém a edição longe da navegação pública; não apaga cópias históricas. Não publique dados sensíveis ou chaves de corretoras em qualquer repositório público.

19. Preservação das conversas e preparação do futuro livro

Problema real: conversas podem deixar de aparecer na tela, ser difíceis de localizar ou conter decisões que ficam perdidas entre mensagens. O histórico do ChatGPT não deve ser o único arquivo do projeto.

Sistema de arquivo recomendado

  1. Manual Mestre: registrar aqui, com data, as decisões relevantes, marcos e procedimentos; este documento é a narrativa durável do projeto.
  2. Diário EGI: guardar reflexões e experiências em caderno próprio, sem substituir seus backups por versões novas não testadas.
  3. RelChat / RelEGI: quando uma conversa contiver uma descoberta relevante, exportar ou copiar um resumo fiel, com data e referência. O ChatGPT não copia automaticamente todas as conversas para o GitHub.
  4. Backup: conservar o histórico de commits do GitHub e também baixar periodicamente o ZIP do repositório; exportar JSON/TXT do caderno de evolução e conferir os arquivos reais.
  5. Livro: organizar as versões posteriores em capítulos cronológicos, distinguindo fatos confirmados, lembranças, hipóteses, tentativas e resultados.

Estrutura inicial do livro (proposta editorial)
